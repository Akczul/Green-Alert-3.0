El instructivo permite tecnologías equivalentes a las ilustradas. **No obliga Java como principal, NestJS, los cinco nombres exactos de motores ni ML**; sí exige tres backends con tecnologías/frameworks diferenciados, cinco motores (tres NoSQL, uno relacional y otro de diferente categoría), cinco módulos, tres mecanismos avanzados y móvil instalable. Se revisan MySQL/MongoDB/Cassandra/Redis/Druid porque son la selección solicitada y encajan en ese mínimo. La caché Redis de p. 4 sí es un requisito explícito. La configuración de proveedores se identifica por código/nombres de variables, **sin mostrar ni validar credenciales privadas**. No se consultó Moodle ni un despliegue remoto. No se ejecutó una auditoría completa de secretos de todo el historial, un pentest ni una auditoría visual/teclado completa. Las ausencias se verifican en este checkout; no se infiere que no existan desarrollos externos.

Estados: **CUMPLE** = evidencia suficiente para ese requisito acotado; **PARCIAL** = una parte existe o está probada; **NO CUMPLE** = falta implementación/artefacto obligatorio o se observó incumplimiento; **NO VERIFICADO** = falta comprobación externa, evento futuro o condición no activada. ## Web, móvil, marca y reutilización

Hay pantallas activas para registro/acceso/recuperación, dashboard, reportes/mapa/alta/detalle/tendencias, perfil/configuración, moderación, administración y entidad. App.jsx y ProtectedRoute protegen rutas por los cuatro roles actuales, además de verificaciones backend. La web usa Inter, paleta verde con hex en tailwind.config.js, assets de logo, Lucide, motion, formularios/componentes reutilizables, estados loading/disabled/toasts y prefers-reduced-motion. Hay aria-label/aria-live y etiquetas, pero **no** evidencia integral de contraste, teclado/foco/lectores de pantalla o tamaño táctil en teléfono. Tener responsive o un service worker de Firebase no produce APK ni cliente React Native.

Para un futuro React Native se pueden reutilizar contratos/DTO, assets, tokens de color/tipografía, validaciones puras y reglas de estado/roles. Axios/AuthContext dependen de baseURL /api, localStorage/window y eventos del navegador: requieren adaptadores de red, almacenamiento seguro y navegación nativa. JSX DOM, Tailwind web, Leaflet y input file no se copian como pantallas nativas. Reutilizar lógica sin prometer una conversión automática. El almacenamiento sensible debe diseñarse para el dispositivo, no AsyncStorage sin protección (Meta Platforms, Inc., s. f.).

## Conclusión de auditoría y decisión requerida antes de implementar

La base web/Express/MySQL es funcional y tiene pruebas sólidas; **no cumple todavía el conjunto obligatorio del proyecto final**. Se conservan como activos: más de cinco módulos, acceso local, hash con sal, límite de intentos, unicidad SQL, refresh transaccional, arquitectura hexagonal de tres módulos, OpenAPI con todas las rutas, datos sintéticos y stack Docker actual. Quedan críticos: dos backends, cuatro motores funcionales, APK, seguridad académica, principal hexagonal completo, dos Compose y entregables del informe.

El [plan de cumplimiento final](plan-cumplimiento-final.md) propone arquitectura y orden sin ejecutar ninguna fase. No se presenta como posible completar de forma responsable todos los faltantes antes del 25/11 desde este checkout. Se debe acordar alcance/capacidad o una ampliación explícita; entregar avances identificados como parciales no equivale a cumplimiento. Se detiene el trabajo al concluir esta auditoría.
